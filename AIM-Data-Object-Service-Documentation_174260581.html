Annotation and Image Markup : AIM Data Object Service Documentation

Created by Klinger, Carolyn (NIH/NCI) [C], last updated on Dec 19, 2013

AIM Data Object Service (DOS) provides a mechanism for imaging applications on various computing platforms to create AIM annotations using RESTFul web services. These web services provide a quick way to add AIM functionality to imaging applications. AIM DOS allows you to create AIM annotations as XML documents. You cna download the AIM DOS XML schema.

To effectively use the AIM DOS XML schema, refer to  Extending the AIM Model. This document describes the AIM DOS XML schema.

The root of the AIM DOS XML schema is the AnnotationCollection element. It has a description attribute used to capture the information about annotations stored in AnnotationCollection. Each AnnotationCollection element has two elements, User and Equipment, shown in Figure 1. User stores information about the person who creates AIM annotations. Equipment stores information about the computing system that the person used to create AIM annotations.


Figure 1, User and Equipment elements

An AnnotationCollection element may have either the ImageAnnotationCollection or AnnotationOfAnnotationCollection element, as shown in Figure 2.


Figure 2, ImageAnnotationCollection or AnnotationOfAnnotationCollection element

The ImageAnnotationCollection element stores a collection of AIM image annotations of the same study and stores patient demographic information and one or more ImageAnnotation elements, as shown in Figure 3.


Figure 3, Study Identification attribute, Person element, and ImageAnnotation element

The ImageAnnotation element annotates a thing found on an image. The thing found may occupy more than one image. The ImageAnnotation element may contain annotation name, comment, and template UID attributes. It shall have information about ImageAnnotationType and ImageReference. It may have ImagingPhysicalEntity, ImagingObservationEntity, Inference, Markup and calculationEntityCollection elements, as shown in Figure 4.


Figure 4, ImageAnnotation element

ImagingPhysicalEntity captures the physical description of an observable thing on an image. In a medical context, it stores information mostly about anatomy. It may have a comment attribute, a QuestionCode, and an ImagingPhysicalEntityCharacteristic element, as shown in Figure 5.

Figure 5, ImagingPhysicalEntity element

The QuestionCode element is an optional element. It has three required attributes and one optional attribute as shown in Figure 6.


Figure 6, QuestionCode element

The AnswerCode element is a required element. It may have more than one possible answer choice. It has the same attribute requirements as QuestionCode and is shown in Figure 7.


Figure 7, AnswerCode element

ImagingPhysicalEntityCharacteristic may have an optional comment attribute and a QuestionCode (shown in Figure 6) element. It has a required AnswerCode (shown in Figure 7) and an optional CharacteristicQuantification element.


Figure 8, ImagingPhysicalEntityCharacteristic element

CharacteristicQuantification has one required attribute and four optional attributes, as shown in Figure 9. It may have a number of NonQuantifiable elements and a collection of Scale, Numerical, Interval, or Quantile elements.


Figure 9, CharacteristicQuantification element

ImagingObservationEntity, shown in Figure 10, captures human or machine observation and interpretation of a thing found on an image. It may have a comment attribute, a QuestionCode, and an ImagingObservationEntityCharacteristic element.


Figure 10, ImagingObservationEntity element

The QuestionCode element is an optional element. It has three required attributes and one optional attribute, as shown in Figure 11.


Figure 11, QuestionCode element

The AnswerCode element is a required element. It may have more than one possible answer choice. It has the same attribute requirements as QuestionCode and is shown in Figure 12.


Figure 12, AnswerCode element

The ImagingPhysicalEntityCharacteristic element, shown in Figure 13, may have an optional comment attribute and a QuestionCode (shown in Figure 11) element. It has a required AnswerCode element (shown in Figure 12) and an optional CharacteristicQuantification element.


Figure 13, ImagingPhysicalEntityCharacteristic element

CharacteristicQuantification has one required attribute and four optional attributes. It may have a number of NonQuantifiable elements and either a collection of Scale, Numerical, Interval, or Quantile elements.
Inference, Figure 14, is a conclusion derived by interpreting image(s) and/or other supplemental information related to the image(s) such as medical history and geographic history. Inference has a comment and an imageEvidence attribute, as well as QuestionCode and AnswerCode elements, which are shown in Figures 11 and 12.


Figure 14. Inference element

ImageAnnotationType, shown in Figure 15, captures a type of annotation such as Target Lesion Complete Response as defined by the DICOM standard.


Figure 15 ImageAnnotationType element

The ImageReference element stores either a Dicom or URI element and is shown in Figure 16.


Figure 16. ImageReference element

The Dicom element stores reference information for an imaging study that complies with the DICOM image information object definition standard. The ImageStudy element stores startTime, startDate, and procedureDescription attributes. It has only one ImageSeries element and may have one referencedDicomObjectCollection element that may have one or more Image elements. The ImageSeries element has two attributes, modality and instanceUid, as shown in Figure 17.


Figure 17. Dicom element

The ImageCollection element, Figure 18, can have one or more Image elements. Image has two attributes, sopClassUid and sopInstanceUid, and the GeneralImage and ImagePlane elements.


Figure 18, ImageCollection and Image elements

referencedDicomObjectCollection Figure 19, may have one or more ReferencedDicomObject elements. The latter has two attributes, modality and sopInstanceUid.


Figure 19, referencedDicomObjectCollection element

URI is a child element of ImageReference. It has two attributes, uri and mimeType. It stores a reference to images.


Figure 20, URI element

Markup, shown in Figure 21, is a child element of ImageAnnotation 1. It has two elements, GeometricShapeEntity and TextAnnotation.


Figure 21, Markup element

GeometricShapeEntity has five attributes and four elements as shown in Figure 22. The attributes are shapeIdentifier, label, description, includeFlag, and comment. The QuestionCode element is the same as Figure 11. InterpolationMethodCode captures a coded term for drawing a geometric shape. Two and three-dimensional shapes capture two and three-dimensional coordinates, respectively.


Figure 22, GeometricShapeEntity element

The TextAnnotation element, shown in Figure 23, has two attributes, text and font. The TwoDimensionGeometricShape and ThreeDimensionGeometricShape elements store coordinates and references to images for text annotation.


Figure 23, TextAnnotation element

calculationEntityCollection, Figure 24, stores one or more calculation results as CalculationEntity. Each CalculationEntity has three attributes, namely uniqueIdentifier, description, and mathML. It also has the QuestionCode and AnswerCode elements, which are shown in Figure 11 and 12. It also has the calculationResultCollection and algorithm element.


Figure 24, calculationEntityCollection element

The calculationResultCollection element, shown in Figure 25, has one or more CalculationResult elements. CalculationResult has type, unitOfMeasure, and value attributes. It has three elements that store coded terms to identify data type (DataTypeCode), encoding (EncodingCode) and compression (CompressionCode) applied to the value attribute. dimensionCollection is used to label, index, and assign the total number of data elements in each dimension.


Figure 25, CalculationResult element

The algorithm element, shown in Figure 26, stores information used to produce the calculation result.


Figure 26, algorithm element

The AnnotationOfAnnotationCollection element may have one or more AnnotationOfAnnotation elements. The AnnotationOfAnnotation element resembles ImageAnnotation (Figure 4) except does not include the Person, ImageReference and Markup elements.
